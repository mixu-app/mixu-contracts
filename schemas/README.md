# Graph pack schemas — version 1

Status: **Frozen** · Schema version: `1` · Owner: mixu-core

These files define what a graph pack contains and what a projection may expose
at a given reveal ordinal. The prose authority is
`mixu-docs` → `docs/specifications/narrative-graph.md`; if the two disagree,
that is a defect in both and must be fixed in one change.

## Files and schemas

| Schema | Purpose | Primary example |
|---|---|---|
| `graph-pack-manifest.schema.json` | Package identity, checksums, provenance, rights basis | `examples/graph-pack-manifest.json` |
| `reveal-anchor.schema.json` | Edition-bound ordinal and normalized locator | `examples/graph/reveal-anchor.json` |
| `entity.schema.json` | Person, persona, location, organization, object | `examples/graph/entity.json` |
| `entity-name.schema.json` | Display name or alias with its own reveal boundary | `examples/graph/entity-name.json` |
| `evidence-anchor.schema.json` | Source location behind a claim, with excerpt policy | `examples/graph/evidence-anchor.json` |
| `event.schema.json` | Story-world happening with optional partial/uncertain time | `examples/graph/event.json` |
| `assertion.schema.json` | Typed claim with attribution and epistemic status | `examples/graph/assertion.json` |
| `assertion-transition.schema.json` | Append-only later status change | `examples/graph/assertion-transition.json` |
| `identity-link.schema.json` | Reveal-scoped same-person link | `examples/graph/identity-link.json` |
| `user-overlay.schema.json` | Private reader annotation referencing stable IDs | `examples/graph/user-overlay.json` |

Every schema carries an absolute `$id` under
`https://schemas.mixu.app/graph/v1/`. Cross-schema references use those ids, so
validation works offline from a local registry and never fetches a URL.

## Field optionality rationale

All schemas enforce `additionalProperties: false`. Every optional field has an explicit design justification:

| Schema | Optional field | Justification for optionality |
|---|---|---|
| `entity` | `canonical_name_id` | An entity may be introduced as an unnamed figure (e.g. "a shadowed figure") before any name is revealed. |
| `entity` | `notes` | Internal extraction remarks; omitted during public distribution or reader sync. |
| `entity-name` | `evidence_anchor_id` | A canonical name may be derived from metadata or publication conventions rather than a specific text excerpt. |
| `reveal-anchor` | `text_hash` | Text verification hash; omitted when source hashing is disabled or text is rights-restricted. |
| `evidence-anchor` | `source_hash` | Verification hash of the anchor segment. |
| `evidence-anchor` | `excerpt` | Bounded quote; strictly omitted under `LOCATOR_ONLY` policy to prevent copyright infringement. |
| `event` | `participant_ids` | Ambient or atmospheric events (e.g., storms, power cuts) have no specific character participants. |
| `event` | `story_time` | Story-world time is often unknown, unstated, or disputed in mystery narratives. |
| `event` | `evidence_anchor_ids` | Composite events synthesized across multiple scenes may lack a single anchor ID. |
| `assertion` | `qualifier` | Free-form qualifiers (location, circumstances) are optional contextual enrichments. |
| `assertion` | `extraction_confidence` | Present only when generated by an automated extraction worker, omitted for human-curated packs. |
| `assertion-transition` | `evidence_anchor_id` | Retractions or status changes may be implicit without a dedicated evidentiary passage. |
| `assertion-transition` | `reason` | Optional human-readable review note explaining the status change. |
| `identity-link` | `evidence_anchor_id` | Unification may be inferred from global case-board deduction rather than a single explicit sentence. |
| `user-overlay` | `device_id` | Optional client hardware identifier for multi-device sync conflict resolution. |
| `user-overlay` | `visibility` | Defaults to `FROM_CREATION` if omitted. |

## Compatibility and versioning semantics

Graph pack format versioning follows semantic rules:

### Non-breaking changes (stays v1)

The following changes are backward compatible and remain in `v1`:

1. Adding an optional property to an existing schema (with default or nullable handling in client parsers).
2. Adding a new schema file for a new independent capability that older clients can safely ignore.
3. Adding new enum values to non-critical qualitative fields where the client fallback is `OTHER` / `UNKNOWN`.
4. Adding documentation, clarifications, or new examples in `examples/`.

### Breaking changes (requires v2)

The following changes break wire compatibility and require incrementing to `v2`:

1. Removing any existing property or renaming a property key.
2. Changing the type or structural constraints of an existing property (e.g., changing string to object, narrowing regex).
3. Promoting an optional property to a required property.
4. Changing the semantics or value ranges of existing enum members (e.g., changing `first_reveal` interpretation).
5. Removing or redefining `$id` URI schemes.

A change requiring `v2` must be introduced in a new `schemas/graph/v2/` directory with a matching ADR in `mixu-docs`, migration guides, and parallel consumer support in `mixu-client` and `mixu-server`.

## Version negotiation protocol

1. **Manifest header:** Every graph pack contains `graph_schema_version: 1` in `graph-pack-manifest.schema.json`.
2. **Client capability check:** The reader client inspects `graph_schema_version` before opening SQLite pack tables:
   - If `graph_schema_version == 1`: loaded directly.
   - If `graph_schema_version > MAX_SUPPORTED_VERSION`: client displays an upgrade notification and rejects loading the incompatible pack to prevent state corruption.
3. **Worker output guarantee:** Extraction pipelines pin their target `graph_schema_version` in worker configuration and validate output batches against this frozen schema set.

## Invariants the schemas cannot express

A schema validates one record. The following are projection rules and must be
enforced by the query layer, with fixtures:

- No projection at ordinal `r` exposes a label, alias, relation, identity
  merge, evidence preview, count or layout hint whose reveal exceeds `r`.
- `assertion_transitions` are append-only; viewing an earlier ordinal shows the
  earlier status, not the latest one.
- `identity_links` at a boundary later than `r` must not merge entities in the
  `r` projection, and must not retroactively rename them.
- `user_overlay` with `visibility = FROM_CREATION` stays hidden during a
  historical replay earlier than `created_at_reveal`.
- Search/FTS/autocomplete are built from the same filtered projection, never
  from the full pack.

## Validation

`tools/validate_contracts.py` (run through `just validate`) checks schema
validity, `$id` uniqueness, local `$ref` resolution, example conformance and
OpenAPI pointer integrity. It must fail when any of those is broken; a gate that
cannot fail is not a gate.
